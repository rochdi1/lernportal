# ArgoCD Local Setup Guide

## Overview
ArgoCD is used to manage GitOps deployments of your learning portal (lernportal) on Kubernetes via GitOps. In this setup you run **Minikube** as the local cluster and **SonarQube** via Docker Compose.

This guide walks through installing ArgoCD inside Minikube, verifying its reachability, setting up GitHub Secrets (`ARGOCD_SERVER`, `ARGOCD_USERNAME`, `ARGOCD_PASSWORD`), and updating the workflow `.github/workflows/cd-argocd.yml`.

---

## Prerequisites
- Linux (Ubuntu/Debian)
- Docker & Docker Compose
- kubectl & minikube installed
- Java 25 (for Gradle)
- Node.js 22 (for Angular)

Make sure you have git configured with username/password.

## 1. Install ArgoCD in Minikube

> **Empfohlene Methode (nur Helm)** – Für ein minimales, reproduzierbares Setup nutzen wir ausschließlich Helm. Die manuelle `kubectl apply`‑Variante ist als Alternative dokumentiert, wird aber aktuell nicht verwendet.

### Option A – Helm (empfohlen)
```bash
helm repo add argo https://argoproj.github.io/helm-charts
helm repo update
helm install argocd argo/argo-cd -n argocd --create-namespace
```

### Option B – Kustomize / OCI manifest (Alternative)
```bash
kubectl create namespace argocd
kubectl apply -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
```

> **Hinweis:** Wenn du Option B verwendest, musst du ggf. zusätzliche CRDs manuell anwenden. Für das Lern‑Setup bleibt Helm der einfachere Weg.

After installation, verify the ArgoCD Service:
```bash
kubectl get svc -n argocd
minikube service list -n argocd   # should show argocd-server
```

If not visible, port‑forward locally:
```bash
kubectl port-forward svc/argocd-server -n argocd 8080:8080
```
Now `http://localhost:8080` is reachable.

## 2. Configure Runner (local runner)

Follow the existing `SETUP_SELF_HOSTED_RUNNER.md`:
- Create directory `~/actions-runner`
- Download latest binary from actions/runner releases.
- Extract, configure with `./config.sh --url https://github.com/rochdi1/lernportal --token <TOKEN> --name local-runner --labels self-hosted,local,docker,k8s,sonarqube`.
- Start the runner (`./run.sh` interactive or `sudo ./svc.sh start`).

Ensure Docker membership: `sudo usermod -aG docker $USER && sudo login`.

---

## 3. Set Up GitHub Secrets

Open repository → Settings → Secrets and variables → Actions → New repository secret.

| Secret name | Example value | Where to get it |
|-------------|---------------|-----------------|
| `ARGOCD_SERVER` | `http://localhost:8080` (after port‑forward) | URL of ArgoCD server |
| `ARGOCD_USERNAME` | `admin` | Default admin user |
| `ARGOCD_PASSWORD` | Your chosen password (default after install may be `admin`) | Reset via `argocd account update-password` |

Add each secret; GitHub will expose them as `${{ secrets.ARGOCD_SERVER }}` etc.

## 5. Test the Workflow

Trigger manually (**Actions → CI → Run workflow**) or push a commit to `main`. The job flow becomes:

1. Checkout repo.
2. Build backend (Gradle).
3. SonarQube Scan.
4. **Install ArgoCD CLI**.
5. Login to ArgoCD (`argocd login ARGOCD_SERVER --username ARGOCD_USERNAME --password ARGOCD_PASSWORD --grpc-web`).
6. Set image tag for matrix apps.
7. Sync & wait.

If any step fails, check logs for missing secrets or wrong ArgoCD URL.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| `argocd: command not found` | CLI not installed or not on PATH | Ensure the “Install ArgoCD CLI” step runs before any `argocd` command. |
| `Invalid credentials` when logging in | Wrong `ARGOCD_SERVER` or password | Double‑check the URL matches where ArgoCD is reachable; confirm password. |
| No ArgoCD services in Minikube | ArgoCD not yet deployed | Run the Helm/Kustomize install again, then re‑apply. |
| Backend builds fail with `sonar.java.binaries` error | Missing build output | Run `./gradlew build -x test` first; ensure `build/classes/java/main` exists. |
